# Software is more traceable than you think

## Cumulative incremental hypergraph pipeline

The [incremental duet](proof/INCREMENTAL.md) adds an executable append-only dependency hypergraph spanning recomputation, linked compilation, certification, independent checking, execution, and actual Lean value proofs. Complete ordered prerequisites and full immutable identities control reuse. Current-head transactions select new versions while history, component artifacts, and earlier proofs remain available.

The delivered reference compiler uses pure exact-integer `const`, `input`, `add`, `mul`, and `neg`. Its kernel driver imports the previous checked module and proves the new compiler/value suffix. Input edits reuse universal compiler proofs while reproving affected actual values. Warm replay, revert, and valid runtime/proof restart add no receipt module. The [generated proof fixtures](examples/incremental/receipts/) are regenerated byte for byte by the examples gate.

Across seven revisions, the cumulative pipeline retains 57 compiler rows and 78 actual-value proofs, compared with 161 of each in seven actual fresh cold rebuilds. A parametric shared-diamond theorem proves `n+1` versus `2^(n+1)-1` stage invocations with the same result. Independent component proofs cover every binary selection; 40 references represent 1,048,576 selectors at 20 coordinates without materializing the tuples.

Voice Two's attacks exposed and repaired mutable dependency metadata, stale current scopes, fabricated matching output observations, inconsistent retained-proof metadata, Python's numeric/Boolean scope aliases, and recursive validation of deep DAGs. A standing contradictory-input counterexample limits the unconditional value theorem to explicitly named captured-trace correctness. The duet states the additional global-environment obligation and the Python-refinement, total-cost, source-fidelity, local-trust, and production-integration boundaries. The existing frozen witness-data pipeline is unchanged.

## The intended claim and the proven boundary

The design goal is to retain software's execution witnesses in an append-only ledger and recover the exact recorded premises of outcomes at symbol or derivation-step grain. Connecting real executions to complete, truthful witnesses remains a separate sensing and lifting obligation.

The generic Lean model proves that the hypergraph fold preserves exactly the nodes and complete derivation records supplied by an arbitrary lifting. Its graph is independent of event order and repeated presentation; the timed fold also ignores its separate `Timed.time` field. An underlying event and its lifting may themselves retain time data. Filtering the stream retracts contributions exactly. The executable `contributor` search succeeds exactly when the queried complete derivation is present in the fold, and returns an actual contributing event from the retained stream. It does not reconstruct that stream or erased `Timed.time` fields from the graph.

A witnessed head alone does **not** guarantee a derivation under an arbitrary lifting. The former `returns_head` assumed a contribution equivalent to its conclusion and ignored its witnessed-head hypothesis; it has been removed. Its general replacement is explicitly named `returns_recorded_edge_weaker`. The narrower `returns_recorded_head` proves head recovery for `recordLift`, which constructs the head and its exact derivation together, with explicit equality decisions. This theorem uses the witnessed-head hypothesis and returns some recorded derivation, without promising unique or causally valid premises.

The [two-voice proof review](proof/REPORT.md) gives the exact statements, standing counterexamples, answers to every attack, and the proves/cannot-say lists. The boundary is exercised by ten additional [return controls](proof/ReturnControls.lean).
